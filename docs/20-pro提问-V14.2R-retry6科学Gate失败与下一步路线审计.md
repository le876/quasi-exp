### 4.5 Gate 定义

| Gate | 注册阈值 |
|---|---:|
| continuation residual | `<= 3 mm` |
| geometry P95 | `<= 0.5°` |
| geometry max | `<= 1.0°` |
| repeat P95 | `<= 0.2°` |
| search coverage Jaccard | `>= 0.95` |
| search beta P95/max | `<= 1.0° / 2.0°` |
| assignment/verified-edge change | `<= 0.05` |

# 审计结论

BACRA V14.2R retry6 是一次**运行完整、证据闭合、科学上正确 fail-closed 的实验**。它不是因为进程崩溃、并行调度错误、artifact 缺失或 solver 大面积失败而没有通过，而是暴露了一个比先前更深的瓶颈：

$$
\boxed{
\text{当前方法已经能找到大范围可行 section，}
\quad
\text{但尚未把冗余逆解中的 canonical“规范”固定下来}
}
$$

这里的“规范”包括两个层面：

1. **全局 branch 身份没有固定：**增加 root 预算后，系统会选择另一张同样可行、但整体相差约 (5^\circ) 的 section。
2. **局部 continuation 规范没有固定：**corrector 只约束末端位置，不约束 fiber 内的零空间坐标，导致同一闭环在不同方向和极小扰动下返回不同的可行 IK 解。

这两种现象本质上来自同一个问题。因为

$$
F:\mathbb R^6\rightarrow\mathbb R^3,
$$

固定末端位置 (x) 后，其逆解集合

$$
\mathcal F_x={\beta\mid F(\beta)=x}
$$

一般仍约有三维自由度。当前代码能够保证 (F(\beta)\approx x)，但还没有完整规定“在 (\mathcal F_x) 上究竟选哪一点”。

因此，当前结果：

* **没有否定**静态 (xyz\rightarrow\beta_6)；
* **没有证明**必须使用 stateful、branch token 或 multiple candidates；
* **不能通过**把 (1^\circ) 阈值直接放宽到 (1.3^\circ)；
* **也不应现在直接进入** 12-patch、meso、5k 或 Student。

下一步应先实施一轮规模很小但机制针对性很强的：

> **BACRA V14.2R retry7 — Gauge-Locked Canonical Identity and Holonomy Decomposition**

先固定 canonical branch，再诊断唯一失败闭环的零空间漂移，随后才重新运行四 patch Gate。

# 2.2 当前名为 `S4_canonical_anchor`，实际上没有强制选择 anchor component

这是本轮最关键的代码语义问题之一。

当前报告中的：

```text

```

只表示 canonical anchor root 仍在 root 列表中，并不表示最终 primary atlas 一定选择包含该 anchor 的 chart component。

实际 component 排序首先比较：

1. component 覆盖节点数；
2. component 中 chart 数；
3. root priority；
4. root key。

也就是说，coverage 的优先级高于 anchor 身份。

因此在 `patch_07` 中：

* canonical anchor root 虽然被保留；
* 但 (R=8) 搜索发现另一张覆盖更完整的 chart；
* selector 选择了另一张 chart；
* 最终 canonical policy 整体改变约 (5^\circ)。

所以当前注册方法的名称和实际行为并不一致：

$$
\text{anchor retained}\neq\text{anchor selected}.
$$

对于论文目标，这种行为没有必要。Student 并不需要搜索意义上的“最优 inverse branch”，只需要一套预先规定、稳定、可执行的 Teacher policy。

更合理的定义是：

> 先固定 canonical anchor；额外 roots 只用于扩展该 anchor 所属 component 的覆盖，不能用一张不兼容的新 branch 取代整套 policy。

# 三、这个唯一 cycle failure 到底证明了什么

## 3.1 它证明了当前 free continuation transport 不是完全闭环一致的

当前 audit 的 path execution 方式是：

1. 从起点的 canonical beta 出发；
2. 沿路径连续 predictor-corrector；
3. 每一步使用上一步实际求出的 beta；
4. 不在中间节点重置到 stored canonical beta；
5. 最后与起点 canonical beta 比较。

因此它测量的是：

$$
H_C
===

d_\beta\left(
\mathcal T_C(c(x_0)),c(x_0)
\right),
$$

其中 (\mathcal T_C) 是 continuation kernel 沿闭环的自由 transport。

这个量本质上是 continuation connection 的 holonomy。

当前反例说明：

$$
H_C>1^\circ
$$

会在某一方向和某些极小扰动下发生。

## 3.2 它尚未证明 stored static field 本身不存在

最终 primary certificate 的唯一 nonverified entity 是这个 fundamental cycle。也就是说：

* 没有 edge entity 失败；
* 没有 persistent numerical failure；
* 其他 root path、multipath 和 cycle entity 均通过；
* 失败是 (1/1{,}890) 个 fundamental cycles；
* 是 (1/8{,}198) 个 schedules；
* 是 (2/49{,}188) 个 executions。

这些比例不能用来自动忽略 max Gate，但它们说明问题高度局部。

更重要的是，一张离散 static field

$$
c:V\rightarrow\mathbb R^6
$$

可能具有良好的逐边一致性，但某个不带 gauge 的自由 continuation kernel 仍然会在长路径上产生 null-space drift。

因此必须区分：

### Static section certificate

检验：

$$
d_\beta\left(
\mathcal T_{i\to j}(c(x_i)),c(x_j)
\right)
$$

是否对每条邻边都足够小。

### Transport certificate

检验：

$$
d_\beta\left(
\mathcal T_P(c(x_0)),c(x_n)
\right)
$$

是否在不重置 canonical state 的长路径上仍稳定。

当前反例首先是一个 **transport robustness counterexample**。它是否同时是 static section 的反例，还需要 prefix-level 和 canonical-reset 对照才能判定。

# 四、代码层面的根因：corrector 没有规定 fiber 内的选择规则

当前 optimized predictor-corrector 的 predictor 使用 weighted damped pseudoinverse：

$$
\beta_{\mathrm{pred}}
=====================

\beta_s
+
J_W^#(x_t-F(\beta_s)).
$$

但后续 bounded least-squares corrector 的目标只有：

$$
\min_\beta
\left|
F(\beta)-x_t
\right|^2,
$$

并没有显式加入：

* 与 predictor 的距离；
* 与 fixed anchor posture 的距离；
* 与父节点 canonical branch 的距离；
* 与多父节点 consensus 的距离；
* 零空间正则项。

由于该问题是 (3) 个末端约束、(6) 个 beta 变量，corrector 面对的是欠定问题。只优化位置 residual，无法唯一确定 fiber 坐标。

因此即使：

$$
F(\beta_a)=F(\beta_b)=x,
$$

仍可能有：

$$
d_\beta(\beta_a,\beta_b)>1^\circ.
$$

retry6 的闭环正好显示了这一点：末端 residual 几乎为零，但 beta 返回值对路径方向和极小扰动敏感。

所以 root-budget 切换和 cycle holonomy 并不是两个毫无关系的偶然问题，它们共同说明：

$$
\boxed{
\text{当前算法只充分规定了任务空间位置，}
\quad
\text{尚未充分规定冗余零空间中的 canonical gauge}
}
$$

# 五、当前 search-stability 实现还存在四个重要审计问题

这些问题不意味着 retry6 的失败无效，但会混淆失败原因，retry7 应一起修复。

## 5.1 所有 contrast 都错误地直接比较到了 (K4/R8) baseline

计划声称执行的是 nested contrasts，但实际比较关系是：

* `main_K1_R5` vs baseline (K4/R8)；
* `root_dropout` vs baseline (K4/R8)；
* `root_order2` vs baseline (K4/R8)；
* `task_graph_refined` vs baseline (K4/R8)。

正确的 nested contrasts 应该是：

| 需要检验的因素          | 正确比较                                |
| ---------------- | ----------------------------------- |
| 预算变化             | (K1/R5) vs (K4/R8)                  |
| root dropout     | dropout vs `main_K1_R5`             |
| root ordering    | order2 vs `main_K1_R5`              |
| graph refinement | refined (K1/R5) vs ordinary (K1/R5) |

目前 `root_dropout` 和 `root_order2` 实际与 `main_K1_R5` 完全一致，却因为都被拿去与 (K4/R8) baseline 比较，所以一起报告约 (5.37^\circ) 的失败。

因此，retry6 把**一次 root-budget branch switch 重复计入了多个 contrast**。

这不会消除 root-budget instability，但应修正实验归因。

## 5.2 当前 budget contrast 同时改变了 (K) 和 (R)

baseline 为：

$$
K=4,\quad R=8,
$$

main 为：

$$
K=1,\quad R=5.
$$

因此现有结果不能严格区分：

* beam width 的影响；
* root 数量的影响。

需要补一个很小的 (2\times2) 定向实验：

| 组合      |
| ------- |
| (K1/R5) |
| (K4/R5) |
| (K1/R8) |
| (K4/R8) |

不过根据当前实现，只有 selected top-1 hypothesis 会继续传播，所以我预计真正起作用的是 root budget，而不是 (K)。这个判断仍应由同 root set 的 (K1/K4) 对照确认。

## 5.3 `true_beam_not_required=true` 当前没有有效证据

search-stability 中所有被用于 beam trigger 的 variants 都是 (K=1)。

而 `alternative_hypothesis_ratio` 是在 beam pruning 后统计的。对于 (K=1)，每个 `(chart,node)` 最多只能保留一个 hypothesis，所以这个比例按结构就几乎必然为 (0)。

因此当前：

```text
true_beam_triggered=false
```

不能解释为“已经证明不需要 true beam”。

它只能解释为：

> 当前 trigger 的统计对象无法观察到被 (K=1) 剪掉的 alternative hypotheses。

retry7 应统计：

* pruning 前 proposal cluster 数；
* K4 下的实际 multiplicity；
* alternative hypothesis 是否位于高中心性节点；
* K1/K4 在相同 roots 下是否改变下游 field 或 certificate。

## 5.4 几何 disagreement 成功后，不会自动尝试 R1/R2

当前 retry 逻辑只在 R0 **solver failure** 时进入 R1/R2。

对于本次失败闭环：

* R0 solver 成功；
* residual 极小；
* geometry gap (>1^\circ)。

程序立即把它分类为 `geometric_branch_disagreement`，不会测试：

* 更小步长；
* weighted DLS；
* SLSQP；
* 更强的 branch-lock。

所以 retry6 尚未回答：

> 这个 disagreement 能否由更细 continuation 或不同 corrector 消除？

下一轮必须强制执行 solver/kernel ablation，而不是依赖现有 retry chain。

## Phase 5：设计 local canonical gauge

### 实验目的

给 continuation 明确规定 fiber 内的选择规则。

### 原理

不再只解：

$$
\min_\beta|F(\beta)-x_t|^2.
$$

而是解一个 lexicographic constrained problem：

$$
\min_\beta
|\beta-\beta_{\mathrm{ref}}|_W^2
$$

满足：

$$
|F(\beta)-x_t|\le\epsilon,\qquad
\beta\in\mathcal B.
$$

其中 (\beta_{\mathrm{ref}}) 只能由：

* source beta；
* Jacobian predictor；
* fixed anchor posture；
* 已认证邻居的多父节点 consensus；

构造，不能直接使用 target canonical beta 作为 pass oracle。

建议比较两个实现：

### G1：predictor-proximal gauge

$$
\beta_{\mathrm{ref}}=\beta_{\mathrm{pred}}.
$$

### G2：multi-parent consensus gauge

若 target 有多个 certified parents：

$$
\beta_{\mathrm{ref}}
====================

\arg\min_\beta
\sum_{p\in\mathcal P}
w_p|\beta-\tilde\beta_{t|p}|_W^2.
$$

## 4.3 实现 gauge-locked continuation

$$
J_{W,\lambda}^{#}

\left(

## J_{W,\lambda}^{#}e_x

### G2：anchor-potential gauge

$$
V_a(\beta)

\left|
\operatorname{wrap}(\beta-\beta_{\mathrm{anchor}})
\right|_{W_a}^2.
$$

G2 仍然只能使用：
